# PicDeck UI／UX／動態 檢查報告

檢查日期：2026-09-20　版本：0.1.0　系統：iOS 27（模擬器 iPhone 18 Pro）

## 這份報告怎麼來的

1. **走遍畫面**：寫了一個自動測試（`testUIAuditTour`），依序走過照片分頁的六個子分頁、側邊欄、篩選選單、多選、資料夾分頁、整理分頁的三個子層、審核畫面、更多分頁，
   **淺色與深色各截一輪，共 32 張**，再拼成總覽圖逐張看。截圖是 606 張測試照片的情況下拍的。
2. **掃程式碼**：用指令找出「只有圖示、沒有給螢幕閱讀器名稱的按鈕」、固定字級、實色背景、觸覺回饋、動畫是否尊重「減少動態效果」。
3. **對照 Liquid Glass 的用法原則**。

> **關於 Apple 頁面**：你貼的兩個連結，內容是「iOS 27／iPadOS 27／macOS 27 設計套件（Figma、Sketch）已於 2026-06-23 發布」，
> 以及設計資源下載頁。它們**沒有提供任何實作規範或 API**，所以本報告的玻璃用法依據的是 SwiftUI 已有的 Liquid Glass 介面
> （`glassEffect`、`GlassEffectContainer`、`interactive()`、`scrollEdgeEffectStyle`），不是那兩個頁面。
> 官方設計套件與 Icon Composer 我沒有下載，也沒有拿來對照。

## 限制（請先知道）

- **只看了靜態截圖與程式碼。** 動畫的順暢度、玻璃的折射與互動、觸覺回饋，模擬器看不到也感覺不到，**必須在真機確認**，
  清單在 [真機安裝與測試指南](./真機安裝與測試指南.md) 的第五節。
- 我沒有對照 Apple 官方 UI 套件，所以「間距、圓角是否精準符合」沒有驗證。
- 動態（動畫）我是從程式碼判斷有沒有做、有沒有尊重系統設定，不是看實際播放。

## 一、已修正

### 1. Liquid Glass

| 位置 | 問題 | 修正 |
| --- | --- | --- |
| 審核畫面頁首 | 關閉鈕是純圖示、標題是實色膠囊、垃圾桶是純圖示，沒有玻璃質感 | 關閉、標題、垃圾桶都改成玻璃，放進同一個玻璃容器，靠近時會融合；點擊範圍固定 44 點 |
| 審核畫面愛心 | 實色半透明底 | 玻璃圓形加粉紅愛心，出現時有縮放淡入 |
| 審核畫面功能列與快速分類列 | 兩塊玻璃各自疊在一起 | 放進同一個玻璃容器，功能列開啟按下回饋（`interactive`） |
| 放大檢視的關閉鈕 | 灰色圓點圖示 | 玻璃圓形 |
| 待刪清單底部 | 實色 `.bar` 底 | 玻璃圓角面板 |
| 拖拉軸把手 | 貼邊半圓，自己畫的材質 | 玻璃圓形，跟右上角篩選鈕同一種 |
| 共用元件 | 每處各寫各的 | 新增 `GlassCircleButton`、`GlassGroup`、`floatingGlass(interactive:tint:)`、`softScrollEdges()`，全專案共用 |

使用原則已寫在 `GlassStyle.swift` 檔頭：**玻璃只給浮在內容上面的操作層**（頁首按鈕、底部功能列、浮動把手），
不拿來做內容卡片；玻璃疊玻璃要用 `GlassGroup` 包起來。

iOS 25 以下會自動退回半透明材質加細邊框，功能不變。

### 2. 深色模式與對比

| 位置 | 問題 | 修正 |
| --- | --- | --- |
| 底部子分類（年月日…） | 沒選中的字用次要色，玻璃疊在花的照片上幾乎看不清 | 改成主要色 78% 不透明度 |
| 多選的功能列 | 圖示與字用主題藍，深色下對比不足 | 改成主要色，只有刪除保留紅色 |
| 審核功能列 | 同上 | 一般用主要色，展開中的那顆才用主題藍 |
| 整理分頁的三個子層 | 同上 | 同子分類 |
| 月檢視的小月曆 | 沒有照片的日子只有 45% 次要色，深色下幾乎消失 | 提高到 75% |

### 3. 版面

| 位置 | 問題 | 修正 |
| --- | --- | --- |
| 側邊欄 | 面板撐滿整個畫面高度，標籤少時是一大塊空的玻璃 | 高度跟著內容走，最高畫面的八成 |
| 整理清單 | 每一列的字都是藍色，像一排連結，讀起來吵 | 主要色文字加右側箭頭，跟系統設定的列表一致 |
| 資料夾分頁 | 只列出平面的相簿，看不到資料夾，跟「整理 → 資料夾及相簿」不一致 | 改成階層顯示，資料夾可展開，跟系統照片一致 |

### 4. 動態與觸覺

| 項目 | 問題 | 修正 |
| --- | --- | --- |
| **減少動態效果** | 19 處動畫都不理會系統的「減少動態效果」 | 新增 `withMotion`，使用者開啟該設定時直接切換不做動畫，全專案改走它 |
| **觸覺回饋** | 整個專案完全沒有 | 整理的每個動作有對應的震動：保留與撤銷輕、喜愛與分類成功、刪除警告；多選勾選有輕震；拖拉軸拖過一個月有輕震 |
| 動作結果提示 | 小字灰色膠囊，壓在標題上 | 放到畫面中間，變大、帶彩色圖示與彈出動畫 |

### 5. 無障礙（螢幕閱讀器）

補上 9 處只有圖示、念不出名稱的按鈕：頁首的選取、篩選、側邊欄，日記的編輯，圖示選擇器的清除與隨機，放大檢視與說明的關閉，審核畫面的關閉與待刪除。

## 二、還沒處理的問題（依重要程度）

### 高

| 問題 | 說明 | 建議 |
| --- | --- | --- |
| **沒有 App 圖示** | 主畫面顯示的是 Xcode 預設的空白格線圖示 | 用 Apple 的 Icon Composer（已在 Xcode 裡）做多層的 Liquid Glass 圖示。圖示是品牌決定，需要你來決定造型 |
| **沒有在真機驗證** | 玻璃、震動、大量照片下的順暢度都只能在真機確認 | 照 [真機安裝與測試指南](./真機安裝與測試指南.md) 做 |
| **拖拉軸在大量照片下的效能** | 「全部」子分頁每張照片一個落點，兩萬張時建立索引偏重 | 真機用實際照片庫量；必要時改成依日期分桶 |

### 中

| 問題 | 說明 | 建議 |
| --- | --- | --- |
| 月檢視小月曆字級 8 點 | 太小，動態字級也不會放大（固定字級共 10 處，多數是圖示或裝飾，只有月曆是文字） | 決定是否放大到 9 到 10 點，代價是卡片變高 |
| 底部分頁列沒有隨捲動縮小 | iOS 26 以上系統的分頁列可以捲動時縮成小膠囊，把空間讓給內容 | 加 `tabBarMinimizeBehavior(.onScrollDown)`；但目前浮在分頁列上方的子分類列需要跟著調整，先不動 |
| 大標題只在部分畫面收合 | 照片分頁的大標題不會隨捲動縮成小標題，佔掉約 130 點 | 需要把主要捲動視圖直接放在導覽的第一層才會連動，要重排版面 |
| 拖拉軸的年份刻度在大量年份時 | 目前是間距不夠就丟掉，可能丟掉使用者想找的那年 | 依縮放程度動態決定要顯示哪些 |
| 篩選選單的標籤層 | 超過十個標籤時只列常用的，其餘進「全部標籤」，找特定標籤要多一步 | 觀察真實使用再決定 |

### 低

| 問題 | 說明 |
| --- | --- |
| 沒有載入骨架畫面 | 整理清單載入 600 張照片要幾秒，期間只有轉圈。可改成骨架列 |
| 沒有教學以外的空狀態插圖 | 空狀態是系統文字加圖示，功能足夠但沒有品牌感 |
| iPad 未支援 | 目前只有 iPhone（`TARGETED_DEVICE_FAMILY = 1`），是企劃的既定範圍 |
| 英文版沒有逐畫面檢查 | 我只看了繁體中文，英文字串長度可能造成截斷 |
| 沒有語音控制、切換控制的驗證 | 只做了旁白名稱的補齊 |

## 三、我判斷「沒問題」的地方

- 照片分頁六個子分頁的資訊層級清楚，淺色與深色都讀得清楚。
- 側邊欄、篩選、多選、建立表單的操作路徑一致，都用同一種「建立在最上面、清單在下面」的模式。
- 時間軸線與圓點細而淡，沒有搶內容。
- 深色模式下的底色與文字對比整體良好（上面列出的例外已修）。
- 審核畫面的手勢與功能列分工清楚：手勢負責保留、喜愛、刪除，按鈕負責需要選擇的動作。

## 四、下一步建議

1. 先在真機走一遍 [真機安裝與測試指南](./真機安裝與測試指南.md) 第五節。
2. 決定 App 圖示的造型，我可以幫你把 Icon Composer 的流程與檔案規格整理出來。
3. 真機上量測大量照片的效能，再決定要不要調整拖拉軸的索引。
